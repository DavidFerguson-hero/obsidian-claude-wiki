# AGENTS.md — schema for the compiled wiki

Instructions for any LLM agent (Claude or otherwise) working in this vault. This file lives in `Admin/`. `Admin/README.md` is the human-facing note; this file is yours. If the two disagree, follow this file and flag the conflict.

Pattern: Andrej Karpathy's "LLM wiki" idea (April 2026). `10 Notes/` is a compiled wiki that agents maintain. The owner feeds it; agents keep it in shape.

### The owner's role

## 2. Note taxonomy

Every note in `10 Notes/` is one of:

- **`compiled`** — built from sources, carries the full frontmatter in §4 and the five sections below. **Everything an agent creates is this.** Template: `Admin/_templates/Compiled Note.md`.
- **`concept`** — the owner's own evergreen prose, usually under a `## Thoughts` heading. **Agents never create these.** Template: `Admin/_templates/Concept Note.md`.
- **`moc`** — an index ("map of content") note, `+` prefix, generated by Dataview queries. Do not hand-maintain lists in them.

### The five sections

| Section | Holds |
| --- | --- |
| `## Core idea` | The claim itself, one paragraph, in your own words. Not a summary of an article. |
| `## Supporting evidence` | Dated, cited evidence entries. **The only section that counts toward `corroborations` and `independent_sources`.** |
| `## Why this matters` | Significance *and* consequence — why the claim is important, and what follows from it for the focus (§0). |
| `## Connections` | `[[wikilinks]]` across the wiki. |
| `## Source` | **Where the owner first encountered this** — the clipping, email, newsletter, conversation or self-written note. Provenance of the *encounter*. |

`## Source` and `sources:` are different things and both are needed. `## Source` is prose: how this reached the owner. `sources:` is a frontmatter list of *resolvable file paths* into `05 Sources/`, `Clippings/` or `40 Archive/Processed captures/`, which is what makes §6 checkable. A free-text string in `sources:` is a defect.

`## Signal assessment` is a sixth, conditional section — see §5. `## Thoughts (original)` appears only on notes reformatted under §3.

There is no `## Implications` section. If you find `## Implications`, `## Key insight` or similar in an older note, fold it into `## Why this matters`.

## 3. The lazy reformat rule

**Do not bulk-convert `concept` notes.** A concept note is reformatted into the compiled schema only when new evidence actually touches it during an ingest.

When that happens:

1. Preserve the owner's prose. Move it under `## Thoughts (original)` — do not paraphrase, compress or "improve" it.
2. Add the compiled sections around it.
3. Add the new evidence with its date and source link.
4. Set `type: compiled` and populate the full frontmatter.

Their words are the substrate. You add structure and evidence around them; you never rewrite them.

## 4. Frontmatter spec

Every compiled note carries:

```yaml
---
title: "Exact note title"
type: compiled              # compiled | concept | moc
pestle: Political           # one of the category folders in §0
confidence: 0.6             # 0.0–1.0, confidence in the core claim
first_seen: 2026-03-12      # earliest dated evidence, or "unknown"
first_seen_basis: evidenced # evidenced | filed | unknown
last_evidence: 2026-07-31   # date of the NEWEST dated evidence entry
corroborations: 4           # distinct URLs in ## Supporting evidence ONLY
independent_sources: 3      # distinct domains among those URLs
signal_strength: 6.8        # 0–10, see §5
strength_basis: derived     # assessed (someone judged it) | derived (computed)
horizon: near               # now (0–1yr) | near (1–3yr) | far (3yr+) | unassessed
so_what: "One specific sentence on what this means for the focus."
sources:                    # resolvable FILE PATHS only, never free text
  - "Clippings/Some article.md"
stale: false
tags: ["topic/AI"]
---
```

### Rules

- **`first_seen`** — the date of the *earliest* evidence, not the note's creation date. If you cannot recover a real date, write `unknown`. **Never invent one.** `first_seen_basis`: `evidenced` (from a dated evidence entry), `filed` (fell back to the note's own date — weaker), or `unknown`.
- **`last_evidence`** — the date of the *newest* dated evidence entry. It measures how fresh the material is, not when a script ran. It only moves forward.
- **`corroborations` and `independent_sources`** — **count only within `## Supporting evidence`.** URLs elsewhere are illustration or provenance, not corroboration. Counting the whole body inflates the numbers badly.
  - `corroborations` = distinct URLs (distinct articles).
  - `independent_sources` = distinct domains. Ten links from one newsletter is `corroborations: 10, independent_sources: 1` — and the second number is the one that should drive confidence.
- **`confidence`** — reflects evidential strength, not how interesting the claim is. Driven by `independent_sources`: 1 → cap 0.4; 2–3 → 0.6; 4+ → 0.75.
- **`stale`** — `true` when a cited source has been superseded or contradicted and the note hasn't been reconciled.
- **`strength_basis`** — `assessed` means someone recorded a judgement on `signal_strength`, `horizon` and `so_what`. **Never overwrite an assessed value.** `derived` means it was computed and may be recomputed freely.
- **`last_used` / `used_count`** — written only by `apply_attention.py` from `Admin/Attention log.md`. **Never set these yourself.** They record that a note changed something the owner did — the one thing the vault cannot infer.

## 5. Signal strength

`signal_strength` (0–10) ranks how strong the evidence for a claim is.

### Weigh

- **Corroboration** — independent sources. Dominant factor.
- **Directionality** — is the evidence moving consistently one way, or oscillating?
- **Proximity** — how directly does it touch the focus (§0)?
- **Surprise** — does it contradict the consensus view? Genuine weak signals usually do.

Do **not** score by counting emphatic words ("breakthrough", "paradigm shift"). A calmly worded, well-corroborated observation outranks a breathless one.

`so_what` must be specific. "This matters for the energy transition" is useless. "Our 2027 electrolyser cost assumptions may be 30% too high" is useful. If you can't be specific, write `so_what: "unclear"` — honest and informative. New notes start at `so_what: "not yet assessed"`.

### When `## Signal assessment` is required

- **Required** when `strength_basis: assessed`. Record the reasoning, so nobody later has to guess whether an 8.4 was earned.
- **Optional** when `strength_basis: derived`. The score is arithmetic; a paragraph restating it is filler. Omit it unless you have a genuine reason the number is wrong.
- **Never** write an assessment to satisfy the schema.

When an agent writes an assessment, mark it so the owner can review it, and stamp the counts it was written against:

```markdown
## Signal assessment
<!-- agent-assessed 2026-09-01 UNREVIEWED -->
<!-- assessed-at: corroborations=6 independent_sources=4 last_evidence=2026-08-28 -->
Reasoning…
```

The owner accepts by deleting the `UNREVIEWED` comment. Lint lists unreviewed assessments, and flags any assessment whose note has since gained evidence (§7 Lint).

## 6. Dual-linking

Every compiled note links in **two directions**:

- **Down to sources** — the `sources:` list, plus inline links at each evidence claim.
- **Across the wiki** — `[[wikilinks]]` under `## Connections`.

This is the main defence against made-up content: every claim should be traceable to a file in `05 Sources/`, `Clippings/` or the archive. **An uncited claim in a compiled note is a defect.** If you must assert something without a source, mark it `<!-- UNCITED -->` so lint catches it.

Wikilinks resolve by file name. Keep every note's file name unique across the vault — never create a second note with an existing name.

## 7. Operations

### Ingest

A new file appears in `00 Inbox/`, `Clippings/` or `05 Sources/`.

1. Read it.
2. Identify which existing notes it touches. **Expect 5–15, not 1.**
3. Update each: add dated evidence, adjust `corroborations`, `independent_sources`, `confidence`, `signal_strength`, `last_evidence`.
   - If the note has a `## Signal assessment`, check whether the new evidence undermines it. Either revise it and update its `assessed-at` stamp, or leave both alone so lint flags it. **Never update the stamp without re-reading the reasoning.**
4. Create a new note only if the topic genuinely has no home. Prefer updating.
5. Report what you changed, with a one-line reason per note.

Evidence entries use this house style:

```markdown
- [Headline or claim](https://url) — one-line interpretation of what it changes. *(2026-07-29)*
```

The `*(YYYY-MM-DD)*` date at the end is what the scripts read. Keep it exactly in that form.

### Archive on completion

**A capture is not processed until it has left the folder it arrived in.** Do both of these in the same run:

1. Set `inbox_processed: true` in the capture's frontmatter.
2. Move it to `40 Archive/Processed captures/`.
   - Dated captures keep their filename.
   - Undated captures get a `_YYYY-MM-DD` suffix (the processing date).
   - If the destination name exists, stop and report it. Never overwrite in `40 Archive/`.
3. Rewrite every `sources:` path in `10 Notes/` that pointed at the old location.
4. Log the move in `00 Inbox/_processing-log.md`: old path → new path, and the notes you updated.

Do **not** move files prefixed `_` in `00 Inbox/`, empty stubs, or anything in `05 Sources/`.

### Query

1. Read `+Home.md` to route.
2. Open the relevant category folder and the notes that matter.
3. Answer from compiled notes. Drop to `05 Sources/` only when provenance is in question.
4. Cite the notes you used.

### Lint

`python3 lint_wiki.py` writes `Admin/_LINT.md`. **It reports; it never edits.** Every finding is a judgement call — silently "fixing" a contradiction is how a wiki drifts away from its sources.

It checks: quiet signals, notes ready for judgement, uncited claims, orphans, dead links, contradiction candidates, missing frontmatter, missing sections, legacy `source:` keys, unreviewed and overtaken assessments, overdue so-whats, and the attention gap.

Two checks are deliberately crude and should be read as prompts, not findings: **contradiction candidates** (most will be complementary) and **attention gap** (high score, never used — either the scoring overrates it or the owner is missing something).

## 9. Standing rules

1. **Never invent a date, a source or a corroboration count.** `unknown` is always acceptable.
2. **Never delete a note.** Propose deletions; the owner decides.
3. **Preserve the owner's prose** when reformatting. Structure around it, never over it.
4. **Never overwrite an `assessed` value** with a computed one.
5. **Every change should be reviewable as a git diff.** Prefer many small edits over wholesale rewrites.
6. **Report uncertainty.** If two sources conflict, say so in the note rather than silently picking one.
7. **Never leave a processed capture in its inbox folder.** Flag and move together (§7).
8. **Never run `git clean` in this vault.** It deletes untracked files permanently, including notes not yet committed.
9. **Never restate this schema in another file.** Copies drift; the copy is the one agents end up reading. Point to this file instead.
