# SIGNALS.md — rules for the weak-signals register

Instructions for the weak-signals agent. This file governs `60 Signals/` the way `AGENTS.md` governs `10 Notes/`. Read both before a run. Where they overlap, `AGENTS.md` wins.

---

## 1. What the register is

The register answers *"what is the big picture, and how is it moving?"* — a level above the notes.

**A signal is a synthesis across notes, never a note.** A signal draws on several knowledge-base notes and says something none of them says alone. If a draft signal restates one note, it is not a signal — delete the draft.

**Size: roughly 1 signal per 10 notes, capped at 25–35 signals.** The value is in what is left out. Pointing a register at every note produces a long list that nobody reads.

**Themes group signals by mechanism, not by topic.** Ask which *dynamic* a signal demonstrates, not which sector it sits in. Themes drift into topic buckets if nobody checks — test membership on every run.

## 2. Write boundaries

| Path | Permission |
| --- | --- |
| `60 Signals/` | **Read/write.** Yours. |
| `10 Notes/` | **Read only** from this task. If a note needs changing, report it. |
| `signals.json` | Generated by `build_signals_json.py`. Never hand-edit. |
| Everything else | Read only. |

The owner feeds the knowledge base and reviews the register. **Never build anything that needs the owner to tag, promote or approve items** for the register to stay current.

## 3. Signal notes

File name: `SIG - Short title.md`. Frontmatter:

```yaml
---
title: "Short title"
type: signal
signal_id: sig_short_title       # stable; never change after creation
theme: "Theme name"
theme_id: T1
strength: emerging               # weak | emerging | established | strong
maturity: 5                      # 0–10: 0 idea, 5 early commercial, 10 mainstream
impact: 7.5                      # 0–10: potential impact on the focus (AGENTS.md §0)
horizon: near                    # now | near | far
first_seen: 2026-05-20           # earliest dated evidence across member notes
last_updated: 2026-09-18
status: active                   # active | watching | retired
origin: "proposed YYYY-MM-DD by the weak-signals agent, from N notes about …"
evidence_notes:                  # the member notes in 10 Notes/ — at least 3
  - "[[Note one]]"
  - "[[Note two]]"
  - "[[Note three]]"
tags: ["signal"]
---
```

`trend` and `momentum` are **not** written by hand. `build_signals_json.py` computes them from the dated evidence in the member notes (last 45 days against the 45 before).

Sections:

- `## Summary` — what is happening, in plain language, one or two paragraphs.
- `## Evidence` — dated paragraphs, newest appended at the bottom, each citing the member note it came from.
- `## So what` — what follows, especially what none of the member notes says. End with the consequence for the focus.
- `## Assessment` — why these maturity, impact and strength scores. **Name what would falsify the signal.**

## 4. Theme notes

File name: `Themes/T1 - Theme name.md`. Each theme carries four things:

- **Tagline** — the claim in one line (in frontmatter as `tagline:`).
- `## Description` — what the pattern is.
- `## Insight` — what the signals imply *together* that none states alone.
- `## Tension` — **the unresolved counter-force. The most valuable field.** A theme without a tension is just a category.

Then a `## Review — YYYY-MM-DD` section appended on each run that touched it.

## 5. The weekly run

1. Read `Admin/AGENTS.md`, this file, and every active signal and theme.
2. Find notes in `10 Notes/` with new dated evidence since the last run (`last_evidence`).
3. For each existing signal: add new evidence to `## Evidence`, review the scores, record changes with reasons.
4. Look for clusters of 3+ notes with no signal home. Propose a new signal only if it says something none of the notes says.
5. **Challenge the themes.** Merge themes that have converged, split ones carrying unrelated signals, retire ones that have stopped explaining anything, propose new ones where signals have no home. Every change is recorded in the theme's review section with its reasoning. "No change" is a fine outcome — say so.
6. Retire signals whose evidence has gone dry for 6+ months, by setting `status: retired`. Never delete.
7. Run `python3 build_signals_json.py`.
8. Write a short run summary at the top of `+Signals.md` (newest first).

## 6. Standing rules

1. Never invent evidence, dates or scores. If a score is a guess, say so in `## Assessment`.
2. Never delete a signal or theme. Retire it.
3. Two themes may contradict each other. The register does not have to pick a winner — record the contradiction in both `## Tension` sections.
4. Keep the old text when you rewrite an Insight or Tension: move it under the review section, marked "previous wording".
